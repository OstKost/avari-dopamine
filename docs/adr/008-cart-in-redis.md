# ADR-008: Корзина в Redis, а не в Postgres

- Статус: accepted
- Дата: 2026-09-18
- Контекст PRD: FR-CART-01

## Контекст

Корзина — высокочастотно изменяемое, эфемерное состояние (add/remove/change qty на каждый клик), не требующее долговременной consistency-гарантии Postgres и не участвующее в аналитике/отчётности напрямую (в отличие от заказа, который переживает в Postgres как immutable record после оформления).

## Решение

- Корзина хранится в Redis как hash: `cart:{user_id}` → `{product_id: quantity, ...}` + отдельный ключ `cart:{user_id}:pickup_point` для выбранного ПВЗ.
- TTL корзины — 7 дней с продлением при каждом обновлении (`EXPIRE` при каждой мутации) — соответствует FR-CART-01 (истекает при неактивности).
- При оформлении заказа (`FR-ORDER-01`) usecase `order.Create`: читает корзину из Redis → валидирует наличие товаров в каталоге (Postgres) → атомарно копирует состав в `order_items` (Postgres, снапшот цен) → очищает ключ корзины в Redis. Эта операция НЕ распределённая транзакция Redis+Postgres: Postgres-запись — источник истины после успешной записи, очистка Redis выполняется после подтверждённого commit (если очистка не удалась — TTL истечёт естественным образом, максимум "устаревшая" корзина проживёт 7 дней без вреда, так как повторное чтение каталога на next add-to-cart переинициализирует актуальные данные).

## Альтернативы

| Вариант | Почему отклонён |
|---|---|
| Корзина в Postgres (таблица `cart_items`) | Избыточная нагрузка на основную БД от высокочастотных мутаций с низкой ценностью данных; не даёт естественного TTL-механизма |
| Корзина в localStorage (клиент) | Продуктовое требование FR-CART-01: "видна между сессиями/устройствами" — требует server-side хранения |
| Корзина как Kafka compacted topic | Избыточная сложность для key-value use case; Kafka здесь — шина событий, не хранилище состояния сессии |

## Последствия

- (+) Дешёвые, быстрые мутации без нагрузки на Postgres.
- (+) Естественный TTL реализует "автоочистку брошенных корзин" без cron-джобы.
- (-) Redis становится источником истины для корзины (не просто кэш) — падение Redis без персистентности = потеря активных корзин; митигируется `appendonly yes` (ADR-002).
