# internal/contracts

Публичные Go-интерфейсы, через которые модули общаются друг с другом
синхронно (ADR-001, ADR-004). Это ЕДИНСТВЕННЫЙ разрешённый способ для
модуля X использовать функциональность модуля Y — прямой импорт
`internal/modules/Y/*` из модуля X запрещён и проверяется `make lint-arch`.

## Правила для агентов, добавляющих контракты

1. Файл контракта называется по модулю-владельцу: `payment.go` объявляет
   интерфейсы, которые реализует модуль `payment` и использует любой другой
   модуль (например `order`).
2. Интерфейс должен быть МИНИМАЛЬНЫМ — только то, что реально нужно
   потребителям, а не полный публичный API модуля. Пример: `order` не
   получает `PaymentRepository`, только `PaymentProvider.Initiate/VerifyWebhook`.
3. Типы данных, пересекающие границу (DTO), объявляются в том же файле
   рядом с интерфейсом — не тащить `domain`-типы модуля-владельца напрямую
   через границу (домен модуля не является частью публичного контракта,
   ADR-004).
4. Композиционный корень (`cmd/server/main.go`, `cmd/worker/main.go`)
   инстанцирует конкретную реализацию модуля и инжектирует её как
   значение интерфейса контракта туда, где он нужен.
